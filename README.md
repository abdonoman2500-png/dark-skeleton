# وَصل — منصة مراسلة بالبريد الإلكتروني

تطبيق Next.js App Router وPostgreSQL/Drizzle بواجهة عربية RTL وواجهة إنجليزية LTR. تظهر للزائر **معاينة موسومة ببيانات توضيحية**؛ الحسابات والمحادثات الفعلية لا تستخدم تلك البيانات. لا يلزم رقم هاتف.

## تقرير التنفيذ والملفات

- `src/db/schema.ts`: الجداول والمفاتيح والفهارس؛ `src/db/index.ts`: الاتصال عبر `DATABASE_URL`.
- `drizzle/0000_initial_wasl.sql` و`drizzle/meta/`: ترحيل أولي لقواعد البيانات الجديدة؛ `drizzle.config.ts`: إعداد Drizzle Kit من البيئة.
- `src/lib/auth.ts`: scrypt، معرفات عشوائية، جلسات مجزأة وملفات ارتباط HttpOnly؛ `src/lib/server.ts`: صلاحيات العضوية والحظر والتحقق من الملفات وWeb Push؛ `src/lib/client.ts`: الأنواع وبيانات المعاينة.
- `src/app/api/[...path]/route.ts`: واجهات الحسابات والمحادثات والوسائط والحالات والمكالمات والإعدادات؛ `src/app/api/health/route.ts`: فحص الصحة.
- `src/components/wasl-app.tsx`, `auth-modal.tsx`, `calls.tsx`, `settings.tsx`, `ui.tsx`: التطبيق والمصادقة وWebRTC والإعدادات والمكونات المشتركة.
- `src/app/page.tsx`, `layout.tsx`, `globals.css`: نقطة الدخول والبيانات الوصفية والتصميم المتجاوب.
- `public/manifest.webmanifest`, `sw.js`, `offline.html`, `icon.svg`, `icon-192.png`, `icon-512.png`, `chat-pattern.svg`: أصول PWA والإشعارات والواجهة.
- `scripts/smoke.mjs`, `scripts/security-smoke.mjs`: اختبارات متصفح وصلاحيات قابلة للإعادة. الاعتماديات تُدار من `package.json` و`package-lock.json` بواسطة npm.

## مخطط قاعدة البيانات

قاعدة البداية فُحصت وكانت خالية من الجداول. أُخذت نسختان احتياطيتان احترازيتان في بيئة التطوير (`/tmp/app_db_before_wasl.dump` و`/tmp/app_db_before_hardening.dump`، وهما مؤقتتان وليستا بديلاً عن نسخ إنتاجية).

- `users` ← `sessions`, `password_resets`, `push_subscriptions`: هوية البريد والمعرّف العام الفريد الثابت، جلسات الأجهزة، الاستعادة والاشتراكات. يرتبط اشتراك الدفع بالجلسة ويحذف عند إلغائها.
- `conversations` ← `conversation_members` ← `users`: محادثات فردية ومجموعات؛ مفتاح فريد للمحادثة الفردية يمنع تكرارها؛ دور العضو ووقت القراءة والكتابة.
- `conversations` ← `messages` ← `message_receipts`, `message_reactions`: نصوص وردود وتعديل وحذف وإيصالات لكل مستلم وتفاعلات.
- `attachments`: بيانات ملفات `bytea` ومعلوماتها، مرتبطة بالمحادثة أو الحالة وبمالكها؛ التحميل يتطلب صلاحية الوصول للعنصر المرتبط.
- `blocked_users`, `reports`: حظر ثنائي التأثير على المحادثات الفردية وبلاغات محفوظة.
- `statuses` ← `status_views`: حالة وجمهورها وتاريخ انتهاء بعد 24 ساعة وعدّاد مشاهدات.
- `calls` ← `call_signals`: سجل المكالمات وإشارات العرض/الإجابة وICE بين المشاركين.

لا يحذف الترحيل الأولي جداول قائمة، لكنه مخصص لقاعدة **جديدة**. القاعدة الحالية أُنشئت باستخدام `drizzle-kit push` قبل إنشاء سجل الترحيل؛ لا تشغّل الترحيل الأولي عليها دون ضبط baseline ومراجعة مسؤول قاعدة البيانات. قبل أي تغيير على قاعدة قائمة: نسخة احتياطية، مراجعة SQL، وترحيل متوافق ومجرّب على نسخة منها.

## التشغيل والإعدادات

1. وفّر Node.js وPostgreSQL واضبط `DATABASE_URL` في البيئة أو `.env`.
2. ثبّت الاعتماديات بـ `npm install`. في قاعدة جديدة فقط، راجع الترحيل ثم استخدم `npx drizzle-kit migrate`؛ أثناء التطوير على قاعدة اختبار يمكن استخدام `npx drizzle-kit push` بعد مراجعة الفروقات. لا تستخدم `push` عشوائياً على بيانات إنتاجية.
3. شغّل التطوير بـ `npm run dev`، أو الإنتاج بـ `npm run build` ثم `npm run start` خلف HTTPS. يجب دعم الطلبات طويلة العمر وحجم الرفع لدى الوكيل، مع حد أقصى للطلب ونسخ احتياطي ومراقبة.
4. الإعدادات الاختيارية على الخادم فقط:
   - `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (مثلاً `mailto:...`) لتوصيل Web Push. توليد المفاتيح: `npx web-push generate-vapid-keys`. لا تضع المفتاح الخاص في العميل.
   - `RESEND_API_KEY`, `MAIL_FROM`, `APP_URL` لاستعادة كلمة المرور عبر Resend، مع نطاق إرسال موثّق ورابط HTTPS ثابت. من دونها يعود المسار بحالة 503 ولا يدّعي إرسال بريد.
   - `STUN_URL` اختياري، والافتراضي خادم STUN عام؛ `TURN_URL`, `TURN_USERNAME`, `TURN_PASSWORD` لتمرير WebRTC عبر TURN. استخدم خادم TURN موثوقاً ويفضّل بيانات قصيرة العمر؛ STUN وحده لا يضمن الاتصال بين الشبكات.

الوسائط المسموحة تُتحقق من نوعها وتوقيعها، وحد كل ملف 10 MiB، وتُخزّن حالياً داخل PostgreSQL. الروابط تتطلب جلسة وعضوية؛ حذف الملف من إدارة التخزين يزيل بياناته. يجب ضبط حد حجم الطلب على وكيل الإنتاج أيضاً، خصوصاً للطلبات المجزأة، ونقل الوسائط إلى تخزين كائنات خاص عند التوسع.

## نتيجة الاختبارات الفعلية

شُغّلت اختبارات API على حسابات اختبار مستقلة: تسجيل حسابات ومعرّفات فريدة، جلستان، بحث دقيق، إعادة استخدام محادثة، إرسال واستقبال وإيصال قراءة، رفع صورة وتنزيلها المصرح ومنع غير المصرح، إنشاء مجموعة وحالة، الحظر، منع طلبات المصادر الأخرى، وإبطال جلسة وحذف اشتراك Push الاختباري المرتبط بها. اختُبرت صلاحيات مشرف المجموعة وإزالة عضو، خصوصية الحالة وعدّاد المشاهدات، وحذف التخزين. بقيت رسالة اختبار محفوظة بعد إعادة تشغيل التطبيق. حسابات وبيانات الاختبار ذات عناوين `example.test` بقيت في قاعدة التطوير ولم تُحذف بيانات مستخدمين قائمة.

شُغّل Chromium فعلياً بجلستي متصفح مستقلتين: التسجيل والبحث والرسائل، رفع وعرض صور وفيديو، تسجيل رسالة صوتية، مكالمتان صوتية ومرئية محليتان بأجهزة ميكروفون/كاميرا **افتراضية**، حالة نصية، تبديل اللغة واتجاهها واستمرار الإعداد، وتحميل manifest والعامل الخدمي. لم تظهر أخطاء JavaScript في تلك الجولة. هذا لا يثبت المكالمات بين شبكات أو أجهزة حقيقية. فحص `npm audit --omit=dev` بعد تحديث الاعتماديات أظهر صفراً من ثغرات الإنتاج المعروفة في وقت الاختبار؛ قد تبقى تحذيرات في اعتماديات التطوير.

لإعادة الاختبار بعد تشغيل الخادم: `npx playwright install --with-deps chromium` ثم `node scripts/smoke.mjs` و`node scripts/security-smoke.mjs`. تنشئ الاختبارات حسابات اختبار ولا تنظفها تلقائياً. اضبط `BASE_URL` إن لم يكن الخادم على `http://127.0.0.1:3000`.

## المكتمل والقيود المهمة

- منفذ: تسجيل ودخول وجلسات وإلغاؤها، بحث بالمعرّف، محادثات محفوظة، إيصالات وكتابة وحضور، تعديل وحذف وردود وتفاعلات وتوجيه **النص**، صفحات قديمة، رفع وعرض الوسائط والتسجيل الصوتي، مجموعات وأدوار، حالات نصية/صورية/مرئية وجمهور محدود ومشاهدات، حظر وبلاغات، إعدادات الملف والخصوصية واللغة والمظهر والأجهزة والتخزين، وPWA مع خدمة Push مشروطة بالإعداد.
- المزامنة والإشارات تستخدم **استقصاءً دورياً** (نحو 3.5 ثوانٍ للمحادثات)، وليست WebSocket؛ لا يوجد طابور إرسال أو قاعدة محلية للعمل دون اتصال. الحالة تُخفى بعد 24 ساعة، لكن تنظيف البيانات المنتهية يحتاج مهمة صيانة مجدولة للإنتاج.
- لا يوجد تشفير طرفي E2EE؛ الرسائل وبيانات الوسائط محفوظة على الخادم، فلا تستخدمه لبيانات تتطلب تشفيراً طرفياً قبل إضافة تصميم ومراجعة أمنية مستقلين. تحديد المعدل الحالي داخل الذاكرة فقط ويحتاج مخزناً مشتركاً وحماية على مستوى الوكيل عند تعدد الخوادم.
- تغيير صورة الملف الشخصي، توجيه المرفقات، جماهير حالات مخصصة، إدارة متقدمة لخصوصية المجموعات، وقائمة تفصيلية بأسماء مشاهدي الحالة ليست مكتملة. البحث في الرسائل من الواجهة يقتصر على الرسائل المحمّلة.
- الاستعادة البريدية وPush بالخلفية وAPNs/TURN تتطلب إعدادات وخدمات خارجية غير متاحة في بيئة الاختبار؛ لم تُختبر رسائل بريد فعلية أو إشعارات والتطبيق مغلق أو اتصال بين شبكات مختلفة. إعادة الاتصال في WebRTC أساسية وتحتاج اختبارات إنتاجية، كما أن تخزين إشارات المكالمات يحتاج سياسة تنظيف.
- فحص أمني مستقل، حماية موزعة من الإساءة، إدارة أسرار ونسخ احتياطي واستعادة واختبارات حمل مطلوبة قبل اعتبار المنصة جاهزة للإنتاج العام.

## تثبيت PWA

- **iPhone/iPad:** افتح رابط HTTPS في Safari، ثم «مشاركة» ← «إضافة إلى الشاشة الرئيسية». إشعارات الويب تتطلب إصدار iOS/iPadOS يدعمها وتطبيقاً مضافاً للشاشة الرئيسية وإذن المستخدم وتهيئة VAPID/APNs Web Push.
- **Android:** افتح رابط HTTPS في Chrome أو متصفح داعم، ثم القائمة ← «تثبيت التطبيق» أو «إضافة إلى الشاشة الرئيسية»، وامنح إذن الإشعارات من إعدادات التطبيق إن رغبت.
- ثُبت عمل manifest والعامل الخدمي في Chromium المحلي، لكن التثبيت الفعلي على أجهزة iPhone وAndroid ووصول Push أثناء إغلاق التطبيق **لم يُختبرا** في هذه البيئة.
